## Implementation decisions

| Decision | Choice | Why |
|---|---|---|
| 1. Service-worker scope | `GET /sw.js` (`PwaController@serviceWorker`) streams `public/build/sw.js` with `Service-Worker-Allowed: /` | `vite-plugin-pwa` writes into `public/build/`, which would pin the worker's scope to `/build/` where it controls no navigations. Serving it from the app root gives scope `/` from the URL path alone — no `.htaccess`/nginx directive to get wrong per host, and feature-testable. 404s cleanly before the first build |
| 2. Page caching | **Authenticated HTML is never cached.** Navigations are network-only with an `/offline` fallback | A literal reading of "network-first for pages" would leave a permission-gated page in the cache for the next user of a shared warehouse device |
| 3. Scan UI | New `GET /scan` screen **and** the same `<x-qr-scanner>` embedded in M10's verify worklist | Before M15 there was no scan entry point anywhere in the UI — `/scan/{tag_number}` only resolved from a label scanned with the phone's *native* camera app |
| 4. Manifest owner | Laravel (`config/pwa.php` → `GET /manifest.webmanifest`), not the plugin | The manifest has no build-time input. Generating it keeps one source of truth, lets it read `config('app.name')`, and makes it assertable without `npm run build` having run |
| 5. Icons | Placeholder PNGs generated from the sidebar's cube glyph, committed to `public/icons/` | `public/build` is gitignored but `public/icons` is not, so they ship with the repo. Swappable for real brand art later |
| 6. `html5-qrcode` loading | Lazy `import()` inside `resources/js/qr-scanner.js`, an Alpine component registered in `app.js` | ~370 kB — it must not load on every page. The import has to live in a bundled module: a dynamic `import()` written inline in an `x-data` attribute is never seen by Vite, so the bare specifier would fail to resolve in the browser |

### Defects found and fixed during implementation

- **Precache URLs were relative.** The injected manifest emitted `assets/app-<hash>.js`, which from a root-scoped worker resolves to `/assets/…` — every precache entry 404s and nothing is ever cached (silently, since `Promise.allSettled` swallows it). Fixed with `injectManifest.modifyURLPrefix: { '': '/build/' }`, and `globIgnores` so the worker does not precache itself.
- **The seeded `Auditor` role lacked `tags.view`.** `ScanController::resolve()` gates on it, so M10's branch routing an auditor into verification was unreachable for the role it was written for — its own test had to grant the permission by hand. Added to `RolePermissionSeeder`.
- **The guest layout had no manifest link**, so the app was not installable from the login screen — the first page a field user sees on a fresh device.
- **`[x-cloak]` had no CSS rule.** Every `x-cloak` block in the app (not just the new install banner) flashed on first paint. Added to `resources/css/app.css`.

### Mobile-responsive pass (375 px)

Existing structure was largely sound — `x-data-table` already wraps tables in `overflow-x-auto`
and `x-filter-bar` already uses `flex-wrap`. Fixes made:

- Movement wizard (`create` + `bulk-create`): the location/department pair was an unconditional
  `grid-cols-2`, leaving ~150 px per select and truncating every name. Now `grid-cols-1 sm:grid-cols-2`.
  Its error line moved from `col-span-2` to `col-span-full`, which would otherwise create an
  implicit second column in the single-column mobile grid.
- Audit verify filter bar: controls kept their intrinsic widths and wrapped into a ragged stack.
  Now `w-full sm:w-auto`.
